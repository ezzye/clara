# Delivery roadmap

## First usable loop

1. Owner completes sign-in and MFA, edits a plan and verifies persistence on a second browser.
2. Verify the installed personal MacBook companion observes only the selected folders and Codex projects.
3. Use one actual project completion and one real meeting as acceptance cases.
4. Review evidence quality; adjust session lengths and preparation lead times from the owner's feedback.

## Meeting preparation, first priority

Connect the work MacBook, exact Chrome work origins and real development goals. Extract meeting details with provenance, cancellations, recurrences and timezone tests. Retrieve linked Jira/Confluence discussions and recent email/Slack context without following embedded instructions. Produce a briefing with purpose, decisions, a short reading sequence, unknowns and questions. Make preparation a real planned activity, then capture meeting follow-up. Work data must remain within the authorized workplace/private-cloud boundary.

## Finishing existing projects, second priority

Expand the initial inventory into an evidence-backed portfolio: current checkout, last verified result, unresolved delivery gap, next valuable milestone, owner effort, dependency and explicit finish criterion. Separate near-finished work from exploratory research. Do not prioritize by recency alone. Link projects to weekly commitments and monthly/yearly outcomes. Add a finish review that checks the usable result, not just passing tests.

## Remaining connectors

- Complete Gmail installed-app OAuth and provenance-preserving appointment/task extraction.
- Add a local WhatsApp adapter for selected conversations, with source dates, commitment review and deduplication; the current browser path requires selected text and manual submission.
- Verify Cowork exports and cross-device identity matching on both Macs.
- Install and test the Windows companion on the actual PC.
- Choose and onboard a regulated, read-only Open Banking provider with verified account coverage.
- Move Codex planning to a dedicated private cloud worker if planning must continue while every laptop is off; keep bounded costs and policy enforcement.
- Schedule narrowly defined public-data DeepSeek jobs after budget and evaluation are configured.

## Reliability before broader autonomy

Device offline queues; idempotent import cursors; source freshness; cancellation recovery; structured observations linked to task IDs; explicit task-to-goal relationships; automatic meeting preparation; full deletion and backup tombstones; short-lived device credentials; stricter field classification; provider spending controls; browser interaction/accessibility tests; user-controlled notification policy. No external messages, purchases, banking actions or project publication without separate explicit authorization.
